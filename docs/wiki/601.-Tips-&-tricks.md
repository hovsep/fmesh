## Mesh configuration

You configure a mesh with options on `fmesh.New`. Each option starts from the defaults and
changes one setting. Anything you don't set keeps its default. See
[Scheduling rules](https://github.com/hovsep/fmesh/wiki/401.-Scheduling-rules) for how the
settings affect a run.

| Setting | Default | Options |
|---------|---------|---------|
| Error handling strategy | `StopOnFirstErrorOrPanic` | `WithErrorHandlingStrategy` (`StopOnFirstErrorOrPanic`, `StopOnFirstPanic`, `IgnoreAll`) |
| Cycles limit | 1000 | `WithCyclesLimit(n)`, `WithUnlimitedCycles()` |
| Time limit | 5s | `WithTimeLimit(d)`, `WithUnlimitedTime()` |
| Cycles history limit (cycles kept in `RuntimeInfo.Cycles`) | unlimited | `WithCyclesHistoryLimit(n)`, `WithUnlimitedCyclesHistory()` |
| Livelock threshold (stalled cycles before `ErrLivelockDetected`) | 2 | `WithLivelockThreshold(n)`, `WithoutLivelockDetection()` |
| Debug (log activation results each cycle) | off | `WithDebug(true)` |

- Limits passed as numbers must be greater than 0. To remove a limit, use the `Unlimited`/`Without` option.
- Other options: `WithDescription`, `WithLogger` (inherited by components without their own logger), `WithMeta` (one metadata entry, `string` or `float64`), `WithPlugins`.

```go
fm, err := fmesh.New("etl",
    fmesh.WithDescription("ETL pipeline"),
    fmesh.WithErrorHandlingStrategy(fmesh.IgnoreAll),
    fmesh.WithCyclesLimit(100),
    fmesh.WithTimeLimit(30*time.Second),
    fmesh.WithDebug(true),
    fmesh.WithLogger(myLogger),
    fmesh.WithMeta("env", "production"),
    fmesh.WithMeta("version", 2.0),
)
```

### Identity, metadata and logging

```go
fm.Name()
fm.Description()

// Metadata mutates in place, like on components and ports
fm.Meta().Set("env", "prod").Set("priority", 1.0)
fm.Meta().ValueOrDefault("env", "dev")

fm.Logger()
fm.IsDebug()
```

### Logging

- A mesh logs with a standard `*log.Logger`, by default prefixed with the mesh name and writing to
  stdout. Set your own with `fmesh.WithLogger(l)`.
- Components added to the mesh **use the mesh logger**, so their lines carry the mesh prefix.
- `component.WithLogger(l)` (or `c.SetLogger(l)`) gives one component its own logger. A component
  logger set this way is never replaced by the mesh logger.
- `fmesh.WithDebug(true)` turns on debug logging: each cycle's activation results, including panic
  stacks. `fm.LogDebug(format, args...)` writes your own message only when debug is on.

```go
logger := log.New(os.Stderr, "orders: ", log.LstdFlags|log.Lmsgprefix)
fm, err := fmesh.New("orders", fmesh.WithLogger(logger), fmesh.WithDebug(true))
fm.LogDebug("seeded %d orders", n) // printed only in debug mode
```

### Removing default limits

The default limits (5 seconds, 1000 cycles) can stop a long run early. Remove them when a run
may legitimately be long:

```go
fm, err := fmesh.New("long-running",
    fmesh.WithUnlimitedCycles(),
    fmesh.WithUnlimitedTime(),
)
```

### Bounding memory on long runs

`RuntimeInfo.Cycles` keeps every cycle by default. The engine needs only the last one; the rest
is for inspection. On long runs, keep a sliding window:

```go
fm, err := fmesh.New("long-running",
    fmesh.WithUnlimitedCycles(),
    fmesh.WithUnlimitedTime(),
    fmesh.WithCyclesHistoryLimit(10), // keep the 10 most recent cycles
)
```

## Signals are shared

Fan-out sends the same `*Signal` to every destination. Never mutate a received payload. Make a
modified copy with `WithMeta`, `WithMetaMany`, `MapPayload` and friends. See
[Caveats](https://github.com/hovsep/fmesh/wiki/603.-Caveats#payloads-are-shared-between-destinations).

## Port lookups can return nil

`ComponentByName`, `InputByName` and `OutputByName` return `nil` for an unknown name. Check when
the name is not a constant:

```go
if p := c.InputByName("data"); p != nil {
    // use p
}
```

These helpers take port names and report the bad name for you: `component.RequireInputs`,
`component.Pipeline`, `port.MultiPipe`, `port.MultiForward`. Prefer them over manual lookups.

## Typed payload reads

Use `sig.As[T]()` or `sig.PayloadOrDefault(d)` instead of a type assertion on `Payload()`. A
failed assertion panics the component when an upstream component changes what it sends.

```go
n, err := sig.As[int]()     // error on a wrong or missing payload
n = sig.PayloadOrDefault(0) // or use a default (T comes from the default)

// Straight from a port; covers an empty group and a wrong type
n, err = this.InputByName("in").Signals().FirstAs[int]()
```

See [Reading typed payloads](https://github.com/hovsep/fmesh/wiki/201.-Signals#reading-typed-payloads).

## Put payloads directly

`PutPayloads` wraps each payload in a signal for you:

```go
err := c.InputByName("in").PutPayloads("hello", "world")
```

## Predicate helpers

Use the built-in signal predicates instead of writing closures:

```go
high := p.Signals().Filter(signal.MetaEquals("priority", "high"))
```
