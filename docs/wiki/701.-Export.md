## Exporting Your Mesh

Export a mesh as data or as a diagram: its structure, or its state after any cycle of a run.

| Format | Package | Module |
|--------|---------|--------|
| JSON | [`json`](https://github.com/hovsep/fmesh-export/tree/main/json) | [fmesh-export](https://github.com/hovsep/fmesh-export) |
| YAML | [`yaml`](https://github.com/hovsep/fmesh-export/tree/main/yaml) | [fmesh-export](https://github.com/hovsep/fmesh-export) |
| [Graphviz DOT](https://graphviz.org) | [`dot`](https://github.com/hovsep/fmesh-export/tree/main/dot) | [fmesh-export](https://github.com/hovsep/fmesh-export) |
| [Mermaid](https://mermaid.js.org) | [`mermaid`](https://github.com/hovsep/fmesh-export/tree/main/mermaid) | [fmesh-export](https://github.com/hovsep/fmesh-export) |
| [D2](https://d2lang.com) | [`d2`](https://github.com/hovsep/fmesh-export/tree/main/d2) | [fmesh-export](https://github.com/hovsep/fmesh-export) |
| [PlantUML](https://plantuml.com) | [`plantuml`](https://github.com/hovsep/fmesh-export/tree/main/plantuml) | [fmesh-export](https://github.com/hovsep/fmesh-export) |

Every format implements the `export.Exporter` interface from the root of fmesh-export
(`import "github.com/hovsep/fmesh-export"`), so you can swap one for another.

```bash
go get github.com/hovsep/fmesh-export/mermaid  # or /json, /yaml, /dot, /d2, /plantuml
```

## One interface

Every exporter implements `export.Exporter`, from the root package of fmesh-export:

```go
// package export — import "github.com/hovsep/fmesh-export"
type Exporter interface {
    Export(fm *fmesh.FMesh) ([]byte, error)                      // the structure
    ExportCycle(fm *fmesh.FMesh, c *cycle.Cycle) ([]byte, error) // the structure + one cycle's results
}
```

- Create an exporter once with its options, for example `mermaid.New()` or `json.New()`, and
  reuse it. It keeps no state besides its options.
- Exporting only reads the mesh. It never changes it.
- The output is deterministic: equal meshes give the same bytes.
- Exporters are not plugins. Nothing is attached to the mesh.
- `ExportCycle` with a nil cycle returns `export.ErrNilCycle`.

## The structure

```go
import "github.com/hovsep/fmesh-export/mermaid"

e := mermaid.New()
src, err := e.Export(fm) // components, ports, pipes, descriptions
if err != nil {
    return err
}
return os.WriteFile("mesh.mmd", src, 0o644)
```

The mesh does not need to run first. The JSON and YAML exporters also include metadata.

## Each cycle

`ExportCycle` draws the mesh as it was in one cycle: each component is colored by how its
activation ended, and failed components show their error. A component with no result had no
input.

**After a run:** `RuntimeInfo.Cycles` holds every cycle.

```go
ri, err := fm.Run(ctx)
if err != nil {
    return err
}
for i, c := range ri.Cycles.All() {
    frame, err := e.ExportCycle(fm, c)
    if err != nil {
        return err
    }
    if err := os.WriteFile(fmt.Sprintf("cycle-%03d.mmd", i+1), frame, 0o644); err != nil {
        return err
    }
}
```

**During a run:** export each cycle as it ends, in an `AfterCycle` hook. Use this for long runs,
or with `fmesh.WithCyclesHistoryLimit`, which keeps only the latest cycles.

```go
fm.SetupHooks(func(h *fmesh.Hooks) {
    h.AfterCycle(func(_ context.Context, cc *fmesh.CycleContext) error {
        frame, err := e.ExportCycle(cc.FMesh, cc.Cycle)
        if err != nil {
            return err
        }
        return os.WriteFile(fmt.Sprintf("cycle-%03d.mmd", cc.Cycle.Number()), frame, 0o644)
    })
})
```

Default colors: green = OK, yellow/gold = no input, red = error, pink = panic, orange = hook failed,
blue / purple = waiting (dropping / keeping inputs). The DOT graph also has a legend with the count
of components in each state. The JSON and YAML exporters list each component's result code and errors.

## Pick a format at run time

The shared interface makes this a map, for example for a CLI flag:

```go
exporters := map[string]export.Exporter{
    "json":    json.New(),
    "mermaid": mermaid.New(),
    "dot":     dot.New(),
}
e, ok := exporters[format]
if !ok {
    return fmt.Errorf("unknown format %q", format)
}
data, err := e.Export(fm)
```

## Options

Options go to `New`. Each one sets one thing on top of the defaults; anything you do not set keeps
its default.

| Package | Options |
|---------|---------|
| `dot` | `WithAttrs(element, attrs)`, `WithResultAttrs(code, attrs)`, `WithComponentLabel(label)` |
| `mermaid` | `WithDirection("TB")` (`LR` default), `WithResultColor(code, color)` |
| `d2` | `WithDirection("down")` (`right` default), `WithResultColor(code, color)` |
| `plantuml` | `WithDirection("top to bottom")` (`"left to right"` default), `WithResultColor(code, color)` |
| `json`, `yaml` | none |

An invalid option, such as an unknown direction, makes `Export` and `ExportCycle` return an error.
Each package README lists the details.

## Rendering

| Format | Command line | Online |
|--------|--------------|--------|
| DOT | `dot -Tsvg mesh.dot -o mesh.svg` ([Graphviz](https://graphviz.org)) | [edotor.net](https://edotor.net) |
| Mermaid | `mmdc -i mesh.mmd -o mesh.svg` ([mermaid-cli](https://github.com/mermaid-js/mermaid-cli)) | [mermaid.live](https://mermaid.live) |
| D2 | `d2 mesh.d2 mesh.svg` ([D2 CLI](https://d2lang.com/tour/install)) | [play.d2lang.com](https://play.d2lang.com) |
| PlantUML | `plantuml -tsvg mesh.puml` (needs Java) | [plantuml.com/plantuml](https://www.plantuml.com/plantuml) |

- **Mermaid** renders in GitHub and GitLab markdown. Put the source in a ` ```mermaid ` block, and
  the diagram can live in your README with no extra tools.
- **PlantUML** files also render in many IDEs and wikis with a PlantUML plugin.
- **Animation** of a per-cycle export: render each cycle to PNG, then join them, for example with
  ImageMagick: `convert -delay 100 -loop 0 cycle-*.png mesh.gif`.

## Tip: an export flag

The mesh is fully built before it runs. So you can put export behind an env variable or CLI flag:
build the mesh, write the diagram, and exit without running.

```go
if os.Getenv("MESH_GRAPH") == "1" {
    src, err := mermaid.New().Export(fm)
    if err != nil {
        return err
    }
    return os.WriteFile(fm.Name()+".mmd", src, 0o644)
}
_, err := fm.Run(ctx)
```

## Writing your own exporter

Implement `fmesh.Visitor` and call `fm.Walk`. `Walk` visits the mesh, then each component followed
by its input and output ports (all by name), then every pipe. Every port is visited before any pipe
that touches it, so an exporter can draw nodes first and edges after.

```go
type counter struct{ components, ports, pipes int }

func (c *counter) VisitMesh(*fmesh.FMesh) error                       { return nil }
func (c *counter) VisitComponent(*component.Component) error          { c.components++; return nil }
func (c *counter) VisitPort(*component.Component, *port.Port) error   { c.ports++; return nil }
func (c *counter) VisitPipe(from, to *port.Port) error                { c.pipes++; return nil }

var stats counter
err := fm.Walk(&stats)
```

Wrap it in a type with `Export` and `ExportCycle`, and add `var _ export.Exporter = (*MyExporter)(nil)`
so the compiler checks the shape. For a new diagram format, see
[Writing a new exporter](https://github.com/hovsep/fmesh-export#writing-a-new-exporter) in the
fmesh-export README.
