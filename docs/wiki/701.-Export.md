## Exporting Your Mesh

Every exporter is a mesh plugin. Attach it with `fmesh.WithPlugins`, build the mesh, then call
`Export()`. For a one-off export of a mesh built without the plugin, each exporter also has a
package function: `jsonexport.Export(fm)`, `dot.Export(fm)`, `mermaid.Export(fm)`.

| Format | Plugin | Per-cycle export |
|--------|--------|------------------|
| JSON | [`plugin/jsonexport`](https://pkg.go.dev/github.com/hovsep/fmesh/plugin/jsonexport) (bundled) | no |
| Graphviz DOT | [`fmesh-graphviz/dot`](https://github.com/hovsep/fmesh-graphviz) | yes |
| Mermaid | `fmesh-mermaid/mermaid` (coming soon) | yes |

All exporters walk the mesh the same way, so the output is deterministic, and exporting never
changes the mesh.

## JSON

```go
import "github.com/hovsep/fmesh/plugin/jsonexport"

exporter := jsonexport.New()
fm, err := fmesh.New("mesh", fmesh.WithPlugins(exporter))
// ... add components and pipes ...

data, err := exporter.Export() // indented JSON: components, ports, pipes, descriptions, metadata
```

## Graphviz DOT

```go
import "github.com/hovsep/fmesh-graphviz/dot"

graphviz := dot.New()
fm, err := fmesh.New("mesh", fmesh.WithPlugins(graphviz))
// ... add components and pipes ...

graph, err := graphviz.Export() // DOT source
_ = os.WriteFile(fm.Name()+".dot", graph, 0o644)
```

The graph shows component and port names, descriptions and pipes. Good component descriptions make
the export document itself. View it on [edotor.net](https://edotor.net), or render it:

```bash
dot -Tsvg mesh.dot -o mesh.svg
```

## Per-cycle graphs

Create the exporter with `WithCycles`. It records every cycle of the next run, then
`ExportCycles()` returns one graph per cycle, with components colored by their activation result.
It is a visual replay of the run:

```go
graphviz := dot.New(dot.WithCycles())
fm, err := fmesh.New("mesh", fmesh.WithPlugins(graphviz))
// ... build and seed the mesh ...

if _, err := fm.Run(ctx); err != nil {
    return err
}
graphs, err := graphviz.ExportCycles()
for i, graph := range graphs {
    _ = os.WriteFile(fmt.Sprintf("cycle-%03d.dot", i+1), graph, 0o644)
}
```

The plugin records cycles itself, so `fmesh.WithCyclesHistoryLimit` does not shorten the replay.

## Tip: an export flag

The mesh is fully built before it runs. So you can put export behind an env variable or CLI flag:
build the mesh, write the graph, and exit without running.

```go
if os.Getenv("MESH_GRAPH") == "1" {
    graph, err := graphviz.Export()
    if err != nil {
        return err
    }
    return os.WriteFile(fm.Name()+".dot", graph, 0o644)
}
_, err := fm.Run(ctx)
```

## Writing your own exporter

Implement `fmesh.Visitor` and call `fm.Walk`. `Walk` visits the mesh, then each component followed
by its input and output ports (all by name), then every pipe. Every port is visited before any pipe
that touches it, so an exporter can draw nodes first and edges after.

```go
type counter struct{ components, ports, pipes int }

func (c *counter) VisitMesh(*fmesh.FMesh) error                       { return nil }
func (c *counter) VisitComponent(*component.Component) error          { c.components++; return nil }
func (c *counter) VisitPort(*component.Component, *port.Port) error   { c.ports++; return nil }
func (c *counter) VisitPipe(from, to *port.Port) error                { c.pipes++; return nil }

var stats counter
err := fm.Walk(&stats)
```

Ship it as a plugin, like the exporters above: `Init` keeps the mesh, and `Export` walks it.
