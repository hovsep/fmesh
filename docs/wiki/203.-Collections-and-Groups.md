## Overview

F-Mesh provides two fundamental abstractions for working with multiple entities: **Collections** and **Groups**. These patterns are used consistently throughout the framework for signals, ports, components, and cycles, providing a unified API for managing sets of entities.

- **Collection** — indexed structure where entities are accessed by unique name
- **Group** — ordered list where entities are accessed by position or iteration

Both share the same read surface — `Len`, `IsEmpty`, `All`, predicate queries, `ForEach` — so what you learn on one type carries to the others.

One rule cuts across everything on this page: **`signal.Group` is copy-on-write, everything else mutates in place.** Methods named `With*`/`Without*` return a new value; methods named `Set*`/`Add*`/`Remove*` change the receiver. The two never mix on one type.

## Collections

Collections are **indexed structures** where each entity has a unique name. They're ideal when you need to access specific entities by their identifiers.

### Characteristics

- **Named access** — retrieve entities by name with `ByName`
- **Unique names** — adding a duplicate name is an error
- **Deterministic order** — every traversal goes in **name order**, stable across runs

That last point is a guarantee, not an accident: iteration order used to be map order, which made identical runs produce different results. Now `ForEach`, `Filter`, `Map`, `Any`, `FindAny` and friends all walk entities sorted by name, and `AllOrdered()` hands you that sorted slice directly.

### Where Collections Are Used

| Type | Description |
|------|-------------|
| `component.Collection` | Set of components accessed by name |
| `port.Collection` | Set of ports accessed by name |

### Basic Operations

```go
// Get component by name (returns nil if not found)
c := fm.Components().ByName("processor")

// Get port by name (returns nil if not found)
p := c.Inputs().ByName("input1")

// Get multiple ports by names (names that match nothing are skipped)
ports := c.Inputs().ByNames("in1", "in2", "in3")

// Check if collection is empty
if fm.Components().IsEmpty() {
    // No components
}

// Get collection size
count := fm.Components().Len()

// All entities, sorted by name
for _, comp := range fm.Components().AllOrdered() {
    fmt.Println(comp.Name())
}
```

`All()` returns a name-keyed map copy; use `AllOrdered()` when you are going to iterate.

### Filtering Collections

```go
// Filter components by predicate (returns a new collection)
activeComponents := fm.Components().Filter(func(c *component.Component) bool {
    return c.Meta().ValueIs("status", "active")
})

// Find first component matching predicate (in name order; nil if none)
first := fm.Components().FindAny(func(c *component.Component) bool {
    return c.Meta().Has("critical")
})

// Check if any component matches
hasActive := fm.Components().AnyMatch(func(c *component.Component) bool {
    return c.Meta().ValueIs("status", "active")
})

// Check if all components match (true on an empty collection)
allActive := fm.Components().Every(func(c *component.Component) bool {
    return c.Meta().ValueIs("status", "active")
})

// Count matching components
activeCount := fm.Components().Count(func(c *component.Component) bool {
    return c.Meta().ValueIs("status", "active")
})
```

> **Note:** `Any()` with no arguments returns the first entity in name order (or nil if empty) — the name says "any" because callers should not depend on which one they get, but it is stable across runs like every traversal. To test a predicate, use `AnyMatch()`.

### Iterating Collections

```go
// Iterate over all components, in name order; stops on first error
err := fm.Components().ForEach(func(c *component.Component) error {
    fmt.Printf("Component: %s\n", c.Name())
    return nil
})

// Map/transform collection (returns error if the mapper produces a duplicate name)
transformed, err := fm.Components().Map(func(c *component.Component) *component.Component {
    c.Meta().Set("processed", "true")
    return c
})
```

### Adding and Removing

Collections mutate in place — these change the receiver:

```go
// Add components to collection (returns error on duplicate)
err := fm.Components().Add(c1, c2, c3)

// Remove components by name (mutates, returns the collection for chaining)
fm.Components().Remove("old-component", "deprecated")
```

To get a subset *without* touching the original, use `Filter` — it returns a new collection.

## Groups

Groups are **ordered lists**. They're ideal when you work with entities that have no names (signals) or where position matters more than identity.

### Characteristics

- **Slice-based** — an ordered list, first to last
- **Insertion order preserved** — what goes in first comes out first
- **Can contain duplicates** — no uniqueness constraint

### Where Groups Are Used

| Type | Mutability | Description |
|------|------------|-------------|
| `signal.Group` | **Copy-on-write** | Ordered signals — a port's buffer, a batch in flight |
| `port.Group` | Mutates in place | Ordered ports — a port's outbound pipes |
| `cycle.Group` | Mutates in place | Cycle history (`RuntimeInfo.Cycles`) |

`signal.Group` is the odd one out on purpose: signals are shared by pointer across pipes, so anything that could change a group another component also sees must return a new value instead.

### Basic Operations

```go
// Get all signals from a port
signals := port.Signals().All()

// Get first / last signal (nil if empty)
first := port.Signals().First()
last := port.Signals().Last()

// Find first matching signal (nil if none)
found := port.Signals().Find(signal.MetaEquals("priority", "high"))

// Check if group is empty
if port.Signals().IsEmpty() {
    // No signals
}

// Get group size
count := port.Signals().Len()
```

### Creating Signal Groups

```go
// Create a group from multiple payloads
group := signal.NewGroup(1, "hello", 3.14, true)

// Grow a group (copy-on-write — assign the result!)
group = group.With(signal.New(42))
group = group.WithPayloads(5, 6, 7)
group = group.Join(otherGroup)
```

### Filtering Groups

```go
// Filter signals by predicate (returns a new group)
highPriority := port.Signals().Filter(signal.MetaEquals("priority", "high"))

// Check if any signal matches
hasUrgent := port.Signals().Any(signal.HasMeta("urgent"))

// Check if all signals match
allProcessed := port.Signals().Every(signal.HasMeta("processed"))
```

### Iterating Groups

There are two main approaches for iterating over signals:

```go
// Approach 1: Using ForEach() — stops on the first error
err := port.Signals().ForEach(func(s *signal.Signal) error {
    fmt.Printf("Signal payload: %v\n", s.Payload())
    return nil
})

// Approach 2: Using All() — when you need the slice
for _, sig := range port.Signals().All() {
    fmt.Printf("Signal payload: %v\n", sig.Payload())
}
```

`ForEachIf(predicate, action)` iterates only the matching signals.

```go
// Map/transform signals (copy-on-write — returns a new group)
doubled := port.Signals().Map(func(s *signal.Signal) *signal.Signal {
    if num, ok := s.Payload().(int); ok {
        return signal.New(num * 2)
    }
    return s
})

// Map only matching signals, keep the rest as-is
doubledInts := port.Signals().MapIf(
    func(s *signal.Signal) bool { _, ok := s.Payload().(int); return ok },
    func(s *signal.Signal) *signal.Signal {
        return signal.New(s.Payload().(int) * 2)
    },
)
```

### Working with Payloads

```go
// Get all payloads
payloads := port.Signals().AllPayloads()

// Get first payload — an empty group is a real runtime state, so this one returns an error
payload, err := port.Signals().FirstPayload()

// Or nil
payload = port.Signals().FirstPayloadOrNil()

// Typed: an error, or the default, on an empty group or a wrong payload type
n, err := port.Signals().FirstAs[int]()
n = port.Signals().FirstPayloadOrDefault(0)   // T inferred from the default
```

## Metadata on Groups and Collections

Every group and collection carries its **own** metadata store (Tier 1). Batch metadata on *contents* (Tier 2) exists on `signal.Group` only:

| Tier | What it touches | Methods | Where |
|------|-----------------|---------|-------|
| 1 — entity's own | The group/collection itself | CoW: `WithMeta` on `signal.Group` · Mutating: `Meta().Set(...)` everywhere else | everywhere |
| 2 — batch on contents | Each contained signal | `WithMetaOnEach`, `WithoutMetaOnEach` | `signal.Group` **only** (copy-on-write) |

Because `signal.Group` is copy-on-write, its `Meta()` returns a **copy** — mutating it changes nothing. Produce a modified group with `WithMeta`:

```go
g.Meta().Set("k", "v")  // mutates a copy; g is unchanged
g = g.WithMeta("k", "v") // the way to do it
```

On the mutating types (`port.Group`, the collections, `cycle.Group`) `Meta()` returns the live store and you change that directly. The mutating types carry no batch-on-contents methods — iterate with `ForEach` and use each element's own store.

## port.Collection batch operations

`port.Collection` supports operating on all ports at once:

```go
// Check readiness across ports
this.Inputs().AllHaveSignals()
this.Inputs().AnyHasSignals()

// Broadcast the same signals to every port in the collection
_ = c.Inputs().PutSignalsOnEach(signal.New(1))

// Flush all output ports (a runtime-path method — takes the context)
_ = c.Outputs().Flush(ctx)

// Pipe every port to every destination (a full cross product)
_ = c.Outputs().PipeEachTo(destPort)

// Aggregate all signals from all ports into one group, in port-name order
allSignals := c.Inputs().Signals()
```

`SetParentComponent` links ports back to their owning component. (Indexed ports are created on components via `component.WithIndexedInputs` / `WithIndexedOutputs` — see [Component](https://github.com/hovsep/fmesh/wiki/301.-Component#indexed-ports).)

## Determinism

Collections and groups are where F-Mesh's [run determinism](https://github.com/hovsep/fmesh/wiki/401.-Scheduling-rules) lives:

1. **Within one port** — signals keep insertion order (FIFO); `signal.Group` is an ordered slice.
2. **Across ports and components** — every `port.Collection` and `component.Collection` traversal goes in name order.

So a mesh with deterministic activation functions produces identical output for identical input, every time. Don't defeat it by iterating `All()`'s map yourself when order matters — use `AllOrdered()` or `ForEach`.

## Error Handling

Methods that can fail return `error` directly. Lookup methods return `nil` when an entity is not found.

```go
// ByName returns nil if not found
c := fm.Components().ByName("missing")
if c == nil {
    return fmt.Errorf("component not found")
}

// ForEach stops on first error
err := fm.Components().ForEach(func(c *component.Component) error {
    return c.OutputByName("out").PutSignals(signal.New("done"))
})
if err != nil {
    return fmt.Errorf("operation failed: %w", err)
}

// Add returns error on duplicate
if err := fm.Components().Add(c); err != nil {
    return err
}
```

### Common Error Scenarios

```go
// Component not found — nil check
c := fm.ComponentByName("missing")
if c == nil { /* handle */ }

// Port not found — nil check
p := c.InputByName("missing")
if p == nil { /* handle */ }

// Empty group — First() returns nil
first := port.Signals().First()
if first == nil { /* no signals */ }
```

Beware the forgiving lookups: `ByNames` silently skips names that match nothing, and `AllHaveSignals()` on the resulting empty collection is vacuously `true` — so a typo reads as "ready". Helpers like `component.RequireInputs` resolve every name first and report the one they could not.

## Common Patterns

### Check if All Ports Have Signals

```go
component.WithActivationFunc(func(ctx context.Context, this *component.Component) error {
    if !this.Inputs().ByNames("in1", "in2").AllHaveSignals() {
        return component.ErrWaitKeepingInputs
    }
    // Process inputs
    return nil
})
```

### Filter and Process Components

```go
_ = fm.Components().
    Filter(func(c *component.Component) bool {
        return c.Meta().ValueIs("criticality", "high")
    }).
    ForEach(func(c *component.Component) error {
        log.Printf("Critical component: %s\n", c.Name())
        return nil
    })
```

### Transform Signal Payloads

```go
// Double all numeric signals, preserving metadata
doubled := port.Signals().MapIf(
    func(s *signal.Signal) bool { _, ok := s.Payload().(int); return ok },
    func(s *signal.Signal) *signal.Signal {
        num := s.Payload().(int)
        return s.MapPayload(func(any) any { return num * 2 })
    },
)
```

## Collection vs Group: When to Use Which

| Scenario | Use Collection | Use Group |
|----------|----------------|-----------|
| Need to access by name | ✅ Yes | ❌ No |
| Position/insertion order is the identity | ❌ No | ✅ Yes |
| Names must be unique | ✅ Yes | ❌ No |
| Anonymous entities (signals) | ❌ No | ✅ Yes |

Both iterate deterministically — collections by name, groups by insertion order.

## API Consistency

One of F-Mesh's strengths is API consistency. The same methods work across different entity types:

### Filtering

```go
fm.Components().Filter(predicate)
c.Inputs().Filter(predicate)
port.Signals().Filter(predicate)
```

### Iteration

```go
fm.Components().ForEach(func(c *component.Component) error { ... })
c.Inputs().ForEach(func(p *port.Port) error { ... })
port.Signals().ForEach(func(s *signal.Signal) error { ... })
```

### Checking Conditions

```go
fm.Components().AnyMatch(predicate)
c.Inputs().AnyMatch(predicate)
port.Signals().Any(predicate)
```

## Summary

- **Collections** are for named access (components, ports); **Groups** are for ordered lists (signals, pipes, cycles)
- **Traversal is deterministic everywhere** — name order for collections, insertion order for groups
- **`signal.Group` is copy-on-write** (`With*` returns a new group, `Meta()` returns a copy); everything else mutates in place (`Set*`/`Add*`/`Remove*`, live stores)
- **Direct error returns** — methods that can fail return `error`; lookups return `nil`
- The shared read surface (`Len`, `IsEmpty`, `All`, `First`, `Find`, `Every`, `Count`, `ForEach`, …) makes the framework easy to learn

Understanding these patterns is fundamental to writing clean, idiomatic F-Mesh code.
