## Overview

Ports are the connection points of components. Components never talk to each other directly (unlike the actor model, e.g. Akka). They only send and receive signals through their own ports.

A component does not know where its signals go. This keeps each component self-contained and reusable.

Full API: [port package](https://pkg.go.dev/github.com/hovsep/fmesh/port).

## Types of ports

- **Input ports** receive signals for the component to process.
- **Output ports** send signals to connected components.

Both are the same type, [`port.Port`](https://pkg.go.dev/github.com/hovsep/fmesh/port#Port). Each port has a `Direction`: `DirectionIn`, `DirectionOut`, or `DirectionUndefined` (misconfigured). Use `IsInput()` / `IsOutput()` to check it.

A pipe always goes from an output port to an input port. `PipeTo` between two inputs or two outputs returns `port.ErrInvalidPipeDirection`.

## Creating ports

### By name (common)

Use component options or methods:

```go
c, err := component.New("processor",
    component.WithInputs("data", "config"),
    component.WithOutputs("result", "logs"),
    component.WithActivationFunc(myFunc),
)

// Or after construction
err = c.AddInputs("control")
err = c.AddOutputs("debug")
```

### Directly (with description and metadata)

Create ports yourself when you need a description or metadata, then attach them:

```go
dataPort, err := port.NewInput("data",
    port.WithDescription("Primary data input"),
    port.WithMeta("type", "primary"),
    port.WithMeta("priority", 1.0), // numeric metadata is float64
)

resultPort, err := port.NewOutput("result", port.WithDescription("Processing results"))
resultPort.Meta().Set("type", "data") // metadata can also be set later, in place

c, err := component.New("processor", component.WithActivationFunc(myFunc))
err = c.AttachInputPorts(dataPort)
err = c.AttachOutputPorts(resultPort)
```

Attaching an output port as an input (or the reverse) returns `port.ErrWrongPortDirection`.

## Internal structure

Each port has:

| Part | Description |
|---|---|
| **Name** | Unique within the component's inputs (or outputs). |
| **Signal buffer** | Holds any number of signals, in insertion order (FIFO). |
| **Pipes** | The outbound connections to other ports. |
| **Metadata** | String and numeric entries. See [Metadata](https://github.com/hovsep/fmesh/wiki/202.-Metadata). |
| **Description** | Optional, set with `WithDescription`. |

`ParentComponent()` returns the owning component (an interface with `Name()`).

When several upstream components feed one input port, their signals arrive in upstream component-name order. See [Scheduling rules](https://github.com/hovsep/fmesh/wiki/401.-Scheduling-rules) for all ordering guarantees.

## Adding signals

```go
err := p.PutSignals(signal.New("data"), signal.New(42)) // signals
err = p.PutPayloads("data", 42)                          // raw payloads
err = p.PutSignalGroups(group1, group2)                  // all signals of the groups
```

All three return an error and fire the port's `OnSignalsAdded` hook.

## Signal forwarding helpers

These functions copy signals from one port to another **now**. They do not clear the source.

```go
// Copy all signals
err := port.ForwardSignals(ctx, source, dest)

// Copy only matching signals
err = port.ForwardWithFilter(ctx, source, dest, signal.MetaEquals("type", "data"))

// Transform, then copy
err = port.ForwardWithMap(ctx, source, dest, func(s *signal.Signal) *signal.Signal {
    return s.MapPayload(func(p any) any { return strings.ToUpper(p.(string)) })
})
```

### Forwarding several pairs at once

`port.MultiForward` forwards a list of source/destination pairs and names the pair that failed:

```go
err := port.MultiForward(ctx,
    port.Pair{From: outer.InputByName("time"), To: inner.InputByName("time")},
    port.Pair{From: outer.InputByName("data"), To: inner.InputByName("data")},
)
```

- A failure names both ends: `forwarding time -> time: ...`.
- A nil port is an error, not a panic: `cannot forward: <missing port> -> time`. So a typo in a port name shows up as an error that names the pair.

[MultiPipe](https://github.com/hovsep/fmesh/wiki/303.-Pipes#wiring-many-pipes-at-once) does the same for pipes.

## Port errors

| Error | When |
|-------|------|
| `ErrInvalidPipeDirection` | `PipeTo` between two ports of the same direction |
| `ErrWrongPortDirection` | Attaching an output port as an input, or the reverse |
| `ErrNilPort` | A nil port passed to `PipeTo`, or a nil port used as a receiver (see below) |
| `ErrInvalidRangeForIndexedGroup` | Invalid index range when creating indexed ports |

### Looking up a port that does not exist

`InputByName`, `OutputByName` and `Collection.ByName` return `nil` for an unknown name. They return no error, so a typo is caught at the first use:

```go
this.OutputByName("outt").PutSignals(signal.New(1)) // the port is "out"
```

```
panicked: port is nil: InputByName, OutputByName and Collection.ByName return nil for a name no port has
```

- `Signals`, `HasSignals`, `PutSignals`, `PutPayloads` and `PutSignalGroups` panic this way on a nil port.
- Inside an activation function the panic is recovered. The run error names the component, and `errors.Is(err, port.ErrNilPort)` matches it.
- The message cannot name the port: a nil pointer has no name. Check the string you passed to the lookup.
- `PipeTo` is different: it returns `ErrNilPort` as a normal error.

## Port hooks

Port hooks watch signal operations on one port:

```go
c.InputByName("data").SetupHooks(func(h *port.Hooks) {
    h.OnSignalsAdded(func(ctx context.Context, hc *port.SignalsAddedContext) error {
        fmt.Printf("port %q received %d signals\n", hc.Port.Name(), len(hc.SignalsAdded))
        return nil
    })
})
```

Available: `OnSignalsAdded`, `OnSignalsDelivered`, `OnClear`, `OnInboundPipe`, `OnOutboundPipe`. Use them for tracing, validation, debugging and metrics. Full details: [Hooks](https://github.com/hovsep/fmesh/wiki/501.-Hooks).

## Groups and collections

Two types hold many ports:

- **`port.Collection`**: ports by name. A component's `Inputs()` and `Outputs()` are collections.
- **`port.Group`**: an ordered list of ports. A port's outbound pipes are a group.

```go
group := port.NewInputGroup("p1", "p2", "p3") // or port.NewOutputGroup(...)
```

Both share the common iteration API (`ForEach`, `Filter`, `Map`, ...). See [Collections and Groups](https://github.com/hovsep/fmesh/wiki/203.-Collections-and-Groups).

To create indexed ports (`worker0 .. worker3`) on a component, see [Indexed ports](https://github.com/hovsep/fmesh/wiki/301.-Component#indexed-ports).
